# Matched-pair columns — re-scope DeepInfra before the first scheduled run

The scheduled job exists and has not run. Before its first fire, the DeepInfra
column changes from "common fleet" to a **matched-pair design**, because the
experiment it serves has sharpened: the cross-provider stability case needs
the same small set on both providers, not coverage.

## The claim being built, so the design serves it

The standardization case is NOT "same model, different levels across
providers" — Rule 1 bars that comparison and FP8-variant disclosure makes it
expected. The defensible exhibits, in ascending strength:

1. **Mechanism flip**: same model, same day, different behaviour class or
   binding stage across providers (descriptive, legitimate, computable from
   round 21 already).
2. **Differential stability**: model X holds within its band on provider A
   and steps on provider B — within-provider variance compared across
   columns. No level comparison anywhere. This is the frequency-regulation
   claim and the pilot's primary target.
3. **Coincident event**: one column fires while the other stays QUIET, same
   day. Cannot be scheduled, only watched for.

The design below maximizes 2 and 3 per dollar.

## The matched set — chosen by rule, pinned before any cross-column trace

Selection rule, applied to the resolved catalogs (not to any outcome):

- Servable on BOTH columns at exact variant, attestation green (the
  round-21 resolution answers this; re-resolve at build, refuse near-misses).
- **One volatile probe**: undamped funnel, known step history —
  DS-V4-Flash if the DeepInfra catalog carries it at exact variant. Its
  Together decision channel already exists with anchors; the DeepInfra twin
  starts NO-ANCHOR.
- **One boring control**: stable, damped, floor-class — Llama-3.3-70B
  expected. The control is what makes any probe divergence attributable to
  the provider rather than the method: a model that holds on both columns
  proves the instrument isn't manufacturing variance.
- **Optionally one third** if the intersection offers it cheaply
  (Qwen-class). Do not force it; two clean pairs beat three ragged ones.

**Pin the selection with the rule text and the resolved variants before the
first DeepInfra serving day.** Choosing the pair after seeing cross-column
traces is selection on the outcome (TRAP 38's cousin), and this instrument's
selections predate its data — that property is the product.

## The reads this design turns on

- **Differential stability** (the pilot's primary): per matched model, the
  within-provider day-over-day trace on each column, side by side. The
  comparison is variance-to-variance, never level-to-level. No new
  machinery — it falls out of the occasion-log rows once both columns have
  anchors.
- **Coincidence row**: already built; the matched pair makes it
  interpretable, since a same-day flag on the same model across columns is
  the two-site detection.
- **Mechanism comparison** ($0, now): round 21's cells vs Together-era
  cells for the overlapping models — route labels and binding stages, as a
  descriptive table with the provenance rule stated. This is exhibit 1 and
  it needs no new serving.
